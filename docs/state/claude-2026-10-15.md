### What happened, in order

1. **"Shouldn't samoshop see how much we sell per product?"** Production had 44
   orders / 53 lines / 3 products / ฿12,785, all `paid`, fee 0, subtotal equal to
   the line sum on every order. The admin had money only as one total. Planned,
   ran `/scrutinize` on the plan (it caught: a deleted product's sales would
   vanish; switching รายรับสะสม to a line sum would part it from Discord; a third
   copy of the stage rule), then built `sales.js` + `admin-sales.js`. Rejected
   alternative: extending พรีออเดอร์ — it counts UNPAID demand and shows no
   money. The handover bar's first palette FAILED the dataviz CVD validator
   (gray beside green); stages are ordinal, so it is a one-hue green ramp with
   red only for มีปัญหา.
2. **Admin polish on the owner's prompt**: the tab strip wrapped into five rows
   on a phone (a third of the screen) → one scrolling row; the orders table was
   a 900px table cut off at the right on a phone → one card per order (CSS grid
   over the same cells); `shop_admin` badge → ผู้ดูแลร้าน; uppercase tracking off
   Thai labels.
3. **"Revenue by size, colour?"** The grid tracked money per cell already; it
   now switches ชิ้น / บาท, and its margins (per size / per colour) are computed
   in `sales.js` from the lines. Per-size prices mean a size's money is not
   pieces × one price; a test has the dearer size earning more than its share.
4. **"Make the admin work better"** — toured all 10 tabs + the order popup first.
   Found: the slip was a ~38px thumbnail in the slip queue (the daily task) and
   the popup; the popup had no phone, order time, pickup or history; nothing said
   what needed attention. Built the ต้องจัดการ row, rebuilt the queue (big slip
   beside the amount, oldest first, wait time, A/R/←/→ incl. Thai ฟ/พ), added
   the popup summary + ประวัติ + a "slip will not load" state.
5. **Bug scans.** Mine found string-compared timestamps. A `/code-review high`
   found 10, all real, all fixed — worst: A/R stayed live on OTHER admin pages
   (verified red with the old check restored). Fixing it, a line-based `sed`
   delete orphaned a CSS rule body that would have eaten the orders phone
   layout; `npm test` and the build were green — hence `css-parses.test.js`.
   A last independent review covered the ยอดขาย commits (see the end of this file).

6. **Independent review of the ยอดขาย commits** found six, all fixed with a test
   each (mutation-checked): the "waiting for slip check" note counted no-slip and
   rejected-slip orders and its button opened an EMPTY queue — now review vs
   ยังไม่ชำระ are split; "ดูคำสั่งซื้อของสินค้านี้" kept the orders tab's own
   แหล่งที่มา and could open an empty list — it now clears every filter; a row's
   แหล่งที่มา came from the product's CURRENT source, not the lines it counted;
   an old line carrying a colour LABEL made a second grid row; the chart's
   readout sat inside `role="img"` (never announced); plus CSV fee row, margin
   %s summing to 100, clamped partial weeks, no "after today" cut, the source
   default re-seeded per account, whole-piece gridlines.
7. **The tour itself wrote once.** Its "no-write" key check trapped only the
   approve button; in the run that restored the bug, R rejected SH9349 on
